Security Advisory — February 2026

AI Agent Security: Real Threats, Real Solutions

The rise of AI agent platforms has created new attack vectors. Malicious actors are now distributing compromised "skills" that can exfiltrate credentials, API keys, and sensitive data. Here's what you need to know.

🚨 Active Threat: Skill-Based Malware

In February 2026, security researchers discovered multiple malicious AI agent skills in public repositories:

  • 1Password Credential Harvesting: A fake "1Password integration" skill was found to intercept and exfiltrate vault credentials during agent operations, affecting users who installed unvetted skills.
  • VirusTotal Detection Reports: Multiple community-submitted skills were flagged by VirusTotal for containing obfuscated code designed to harvest API keys and tokens from agent environments.
  • Supply Chain Attacks: Compromised dependencies in popular skill packages were identified, injecting malicious payloads during installation.

These incidents underscore a critical reality: AI agents operate with elevated privileges, and every skill you install extends your attack surface.

Threat Landscape

Why AI Agent Skills Are a Security Risk

Unlike traditional software, AI agent skills can execute arbitrary actions with access to your credentials, file system, and connected services.

🎭

Credential Theft

Malicious skills can intercept credentials passed to agents, including OAuth tokens, API keys, and password manager vault access.

Source: 1Password incident, Feb 2026
📤

Data Exfiltration

Skills with network access can silently send sensitive documents, code, and conversations to external servers without user awareness.

Source: VirusTotal reports, Feb 2026
🔗

Supply Chain Attacks

Compromised dependencies in skill packages can inject malicious code during installation, bypassing surface-level code review.

Source: NPM security advisories
🤖

Agent Hijacking

Prompt injection via malicious skills can redirect agent behavior, causing it to perform unauthorized actions on the user's behalf.

Source: OWASP LLM Top 10
